# গো-ল্যাং এ ভেরিয়েবল শ্যাডোয়িং (Variable Shadowing) কী?

গো-ল্যাং (Go) এ **Variable Shadowing** ঘটে তখন, যখন কোনো একটি নির্দিষ্ট স্কোপের (যেমন: ফাংশন, if-ব্লক বা লুপ) ভেতরে এমন একটি ভেরিয়েবল ডিক্লেয়ার করা হয় যার নাম বাইরের স্কোপের কোনো ভেরিয়েবলের নামের সাথে মিলে যায়।

সহজ কথায়, ভেতরের ভেরিয়েবলটি বাইরের ভেরিয়েবলটিকে "আড়াল" (Shadow) করে ফেলে। ফলে ওই ব্লকের ভেতরে বাইরের ভেরিয়েবলটি আর অ্যাক্সেস করা যায় না।

## একটি কোডের ধাপে ধাপে ব্যাখ্যা

নিচে দেওয়া কোডটি কেন ভিন্ন ভিন্ন আউটপুট দিচ্ছে, তা নিচে বিশ্লেষণ করা হলো:

```go
package main
import "fmt"

var a = 10 // গ্লোবাল ভেরিয়েবল a
var b = 15 // গ্লোবাল ভেরিয়েবল b

func main() {
  age := 29

  if age >= 18 {
    a := 47 // এখানে শ্যাডোয়িং হচ্ছে (নতুন লোকাল ভেরিয়েবল)
    b = 20  // এখানে ভ্যালু পরিবর্তন হচ্ছে (গ্লোবাল ভেরিয়েবল)
    fmt.Println("ব্লকের ভেতরে A: ", a) // আউটপুট: 47
    fmt.Println("ব্লকের ভেতরে B: ", b) // আউটপুট: 20
  }

  fmt.Println("ব্লকের বাইরে A: ", a) // আউটপুট: 10 (আগের মতই আছে)
  fmt.Println("ব্লকের বাইরে B: ", b) // আউটপুট: 20 (পরিবর্তন হয়ে গেছে)
}

```

### ১. মেমোরিতে কী ঘটছে?

- **গ্লোবাল পর্যায়:** শুরুতে মেমোরিতে `a = 10` এবং `b = 15` সেট করা হয়।
- **if-ব্লকের ভেতরে `a := 47`:** এখানে `:=` (Short Declaration) ব্যবহার করার কারণে গো-ল্যাং মেমোরিতে সম্পূর্ণ নতুন একটি ভেরিয়েবল `a` তৈরি করেছে। এটি বাইরের `a`-এর মান পরিবর্তন না করে তাকে সাময়িকভাবে আড়াল করে দেয়।
- **if-ব্লকের ভেতরে `b = 20`:** এখানে কোনো `:` নেই। তাই এটি নতুন ভেরিয়েবল তৈরি না করে সরাসরি গ্লোবাল `b`-এর মেমোরি লোকেশনে গিয়ে মান পরিবর্তন করে দিয়েছে।

### ২. আউটপুট কেন আলাদা?

| ভেরিয়েবল | অপারেটর | কেন এমন হলো?                                                       | শেষ ফলাফল (মেইন ফাংশনে) |
| --------- | ------- | ------------------------------------------------------------------ | ----------------------- |
| **a**     | `:=`    | নতুন লোকাল ভেরিয়েবল তৈরি হয়েছে। তাই ব্লকের বাইরের `a` অপরিবর্তিত। | **10**                  |
| **b**     | `=`     | সরাসরি গ্লোবাল ভেরিয়েবলকে আপডেট করা হয়েছে।                        | **20**                  |

## এটি কেন বিপজ্জনক হতে পারে?

ডেভেলপাররা অনেক সময় ভুল করে `err :=` ব্যবহার করে ফেলেন, যার ফলে বাইরের এরর ভেরিয়েবলটি আপডেট না হয়ে নতুন একটি লোকাল এরর ভেরিয়েবল তৈরি হয়। এর ফলে লজিক এরর হতে পারে যা খুঁজে পাওয়া কঠিন।

### সমাধান কী?

১. যদি বাইরের ভেরিয়েবল আপডেট করতে চান, তবে শুধু `=` ব্যবহার করুন।
২. ভেরিয়েবলের নাম আলাদা রাখার চেষ্টা করুন।
৩. কোড চেক করার জন্য `go vet` টুল ব্যবহার করুন।

নিচে এরর হ্যান্ডলিংয়ের (Error Handling) ক্ষেত্রে ভেরিয়েবল শ্যাডোয়িং কীভাবে বড় ধরণের বাগ (Bug) তৈরি করতে পারে, তার একটি বাস্তব উদাহরণ দেওয়া হলো:

## উদাহরণ

### ১. ভুল কোডের উদাহরণ (Shadowing Bug)

ধরা যাক, আপনি একটি ফাইল ওপেন করতে চাচ্ছেন এবং সেই এররটি (`err`) পরে চেক করতে চাচ্ছেন।

```go
func main() {
    var err error // এখানে 'err' ডিক্লেয়ার করা হলো

    if true {
        // ভুল: এখানে := ব্যবহারের ফলে নতুন একটি 'err' তৈরি হয়েছে
        // এটি বাইরের 'err' কে শ্যাডো করছে
        data, err := os.Open("test.txt")
        if err != nil {
            fmt.Println("ফাইল খুলতে সমস্যা:", err)
        }
        _ = data
    }

    // সাবধান! এখানে 'err' সব সময় nil থাকবে
    // কারণ if ব্লকের ভেতরের 'err' বাইরে আসেনি
    if err != nil {
        fmt.Println("এই লাইনটি কখনোই প্রিন্ট হবে না!")
    }
}

```

### ২. এটি কেন সমস্যা?

উপরের কোডে `if` ব্লকের ভেতরে `data, err :=` ব্যবহার করার কারণে একটি নতুন লোকাল `err` তৈরি হয়েছে। ফাইল ওপেন করতে গিয়ে যদি কোনো সমস্যাও হয়, তবে সেই এরর মেসেজটি শুধুমাত্র ওই `if` ব্লকের ভেতরেই সীমাবদ্ধ থাকবে। ব্লকের বাইরে এসে আপনি যখন `err != nil` চেক করবেন, তখন সেটি সবসময় `nil` দেখাবে কারণ বাইরের মূল `err` ভেরিয়েবলটি কখনোই আপডেট হয়নি।

### ৩. সঠিক সমাধান (Correct Way)

এই সমস্যা এড়ানোর জন্য আমাদের ভেরিয়েবল আগে ডিক্লেয়ার করে নিতে হবে অথবা `:=` এর বদলে `=` ব্যবহার করতে হবে।

```go
func main() {
    var err error
    var data *os.File

    if true {
        // সঠিক পদ্ধতি: নতুন ভেরিয়েবল তৈরি না করে মান অ্যাসাইন করা
        data, err = os.Open("test.txt")
        if err != nil {
            return
        }
    }

    // এখন এখানে সঠিক এরর পাওয়া যাবে
    if err != nil {
        fmt.Println("এখান থেকে এরর হ্যান্ডেল করা সম্ভব")
    }
}

```

### ৪. মনে রাখার সহজ উপায়

| আপনি যা করতে চান                  | যা ব্যবহার করবেন         |
| --------------------------------- | ------------------------ |
| নতুন ভেরিয়েবল তৈরি করা           | `:=` (Short Declaration) |
| আগের ভেরিয়েবলের মান পরিবর্তন করা | `=` (Assignment)         |
