Go-তে **Function Expression** এবং ফাংশন ডিক্লারেশনের মধ্যে কিছু গুরুত্বপূর্ণ পার্থক্য রয়েছে যা আপনার কোড রান করার সময় প্রভাব ফেলে। নিচে সহজভাবে বিষয়টি ব্যাখ্যা করা হলো:

## ১. Function Expression কী?

Go-তে যখন আপনি একটি ফাংশনকে একটি **Variable (ভেরিয়েবল)** এর মধ্যে অ্যাসাইন করেন, তখন তাকে **Function Expression** বলা হয়। এক্ষেত্রে ফাংশনটির সাধারণত কোনো নাম থাকে না (যাকে Anonymous Function বলা হয়)।

**উদাহরণ:**

```go
myFunc := func() {
    fmt.Println("এটি একটি Function Expression")
}
myFunc() // ভেরিয়েবলের মাধ্যমে কল করা

```

## ২. কেন ডিক্লেয়ার করার আগে এটি কল করা যায় না?

Function expression মূলত একটি **Variable declaration**-এর মতো কাজ করে। Go-তে কোনো ভেরিয়েবল ব্যবহার করার আগে অবশ্যই সেটি তৈরি (initialize) করতে হয়।

যখন আপনি `myFunc := func() {}` লিখছেন, তখন কম্পিউটার প্রথমে একটি ভেরিয়েবল তৈরি করে এবং তারপর তাতে ফাংশনটি জমা রাখে। আপনি যদি এই লাইনটির আগেই `myFunc()` কল করেন, তবে কম্পিউটার ওই ভেরিয়েবলটি খুঁজে পাবে না কারণ সেটি তখনো তৈরিই হয়নি। এটি একটি লিনিয়ার বা ক্রমানুসারে চলা প্রক্রিয়া।

## ৩. Go-তে কি ডিক্লেয়ার করার আগে কোনো ফাংশন কল করা সম্ভব?

**হ্যাঁ, সম্ভব।** তবে সেটি শুধুমাত্র **Standard Function Declaration**-এর ক্ষেত্রে।

Go-তে যদি আপনি প্যাকেজ লেভেলে কোনো ফাংশন ডিক্লেয়ার করেন (অর্থাৎ ভেরিয়েবলে না রেখে সরাসরি নাম দিয়ে তৈরি করেন), তবে আপনি সেটি কোডের যেকোনো জায়গা থেকে কল করতে পারবেন, এমনকি ফাংশনটি নিচে লেখা থাকলেও।

**উদাহরণ:**

```go
func main() {
    sayHello() // আগে কল করা হয়েছে, এটি কাজ করবে!
}

func sayHello() {
    fmt.Println("হ্যালো!")
}

```

### কেন এটি কাজ করে?

Go কম্পাইলার কোড রান করার আগে পুরো ফাইলটি একবার স্ক্যান করে দেখে নেয় কোথায় কোন ফাংশন আছে। একে বলা হয় **"Lexical Scoping"**। এই স্ক্যানিং প্রক্রিয়ার কারণে সাধারণ ফাংশনগুলো কোডের উপরে না নিচে আছে তা নিয়ে কম্পাইলারের সমস্যা হয় না। কিন্তু Function Expression যেহেতু ভেরিয়েবল হিসেবে গণ্য হয়, তাই সেটি রান-টাইমে ক্রমানুসারে কাজ করে।

## মূল পার্থক্য একনজরে

| বৈশিষ্ট্য           | Standard Function     | Function Expression      |
| ------------------- | --------------------- | ------------------------ |
| **সিনট্যাক্স**      | `func Name() { ... }` | `name := func() { ... }` |
| **আগে কল করা যায়?** | **হ্যাঁ**             | **না**                   |
| **স্কোপ**           | প্যাকেজ লেভেল         | লোকাল (ভেরিয়েবলের মতো)   |

---

Go-তে যখন আপনি `main()` ফাংশনের **ভেতরে** আরেকটি ফাংশন ডিক্লেয়ার করেন, তখন সেটি আর সাধারণ ফাংশন থাকে না, বরং সেটি একটি **Local Function** বা **Nested Function** হিসেবে কাজ করে।

এর ফলে যা যা ঘটে, তা নিচে বিস্তারিত আলোচনা করা হলো:

## ১. নাম দিয়ে ডিক্লেয়ার করা যায় না (Syntax Rule)

Go-তে কোনো ফাংশনের ভেতরে সরাসরি `func Name() {}` এভাবে ফাংশন তৈরি করা যায় না। এটি করলে কম্পাইলার এরর দেবে। আপনাকে অবশ্যই **Function Expression** ব্যবহার করতে হবে (অর্থাৎ একটি ভেরিয়েবলের মধ্যে ফাংশনটি রাখতে হবে)।

**ভুল পদ্ধতি:**

```go
func main() {
    func myInsideFunc() { // এটি Error দেবে
        fmt.Println("Hello")
    }
}

```

**সঠিক পদ্ধতি:**

```go
func main() {
    myInsideFunc := func() { // এটি কাজ করবে
        fmt.Println("এটি একটি Local Function")
    }
    myInsideFunc()
}

```

## ২. স্কোপিং এবং ভিজিবিলিটি (Scope)

যখন আপনি `main()` এর ভেতরে একটি ফাংশন তৈরি করেন, তখন সেটির ক্ষমতা বা স্কোপ খুব সীমিত হয়ে যায়:

- **সীমিত অ্যাক্সেস:** এই ফাংশনটি শুধুমাত্র `main()` ফাংশনের ভেতর থেকেই কল করা যাবে। প্যাকেজের অন্য কোনো ফাংশন (যেমন `func test()`) একে খুঁজে পাবে না।
- **জীবনকাল:** `main()` ফাংশন যখন শেষ হয়ে যাবে, এই লোকাল ফাংশনটিও মেমোরি থেকে মুছে যাবে।

## ৩. ক্লোজার (Closures) এর সুবিধা

ফাংশনের ভেতরে ফাংশন ডিক্লেয়ার করার সবচেয়ে বড় সুবিধা হলো **Closure**। এর মাধ্যমে ভেতরের ফাংশনটি তার বাইরের ফাংশনের ভেরিয়েবলগুলোকে অ্যাক্সেস করতে পারে।

**উদাহরণ:**

```go
func main() {
    message := "হ্যালো"

    myFunc := func() {
        // বাইরের 'message' ভেরিয়েবলটি এখানে ব্যবহার করা যাচ্ছে
        fmt.Println(message)
    }

    myFunc()
}

```

## ৪. ডিক্লেয়ার করার আগে কল করা অসম্ভব

আগে যেমনটি আলোচনা করেছি, `main()` এর ভেতরে ফাংশন যেহেতু একটি ভেরিয়েবল হিসেবে তৈরি হয়, তাই আপনি ওই লাইনের আগে একে কল করতে পারবেন না।

```go
func main() {
    myFunc() // ERROR: myFunc undefined

    myFunc := func() {
        fmt.Println("Hi")
    }
}

```

### সারসংক্ষেপ

আপনি যদি `main()` এর ভেতরে ফাংশন ডিক্লেয়ার করেন:

1. আপনাকে **Anonymous function** বা **Variable** ব্যবহার করতে হবে।
2. এটি শুধুমাত্র `main()` এর ভেতরেই কাজ করবে।
3. এটি বাইরের ভেরিয়েবলগুলোকে "Capture" করতে পারবে (Closure)।
4. এটি লিনিয়ারলি কাজ করবে, তাই আগে ডিক্লেয়ার করতে হবে, পরে কল।

---

**Package Level**-এ ফাংশন ডিক্লেয়ার করলে সেটি `main()` ফাংশনের ভেতরের ফাংশনের মতো কাজ করে না। এই দুটির মধ্যে বিশাল পার্থক্য রয়েছে।

যখন আপনি প্যাকেজ লেভেলে (অর্থাৎ কোনো ফাংশনের বাইরে সরাসরি ফাইলে) একটি ফাংশন লেখেন, তখন সেটি **Standard Function Declaration** হিসেবে গণ্য হয়। এর বৈশিষ্ট্যগুলো নিচে দেওয়া হলো:

## ১. ডিক্লেয়ার করার আগেই কল করা যায় (Hoisting-এর মতো সুবিধা)

প্যাকেজ লেভেলে ফাংশন থাকলে আপনি সেটি কোডের যেকোনো জায়গায় কল করতে পারেন। Go কম্পাইলার প্রথমে পুরো প্যাকেজটি পড়ে নেয়, তাই ফাংশনটি ফাইলের শেষে থাকলেও শুরুতে কল করলে কোনো সমস্যা হয় না।

```go
package main
import "fmt"

func main() {
    result := mySum(10, 20) // কাজ করবে! (আগে কল করা হয়েছে)
    fmt.Println(result)
}

func mySum(a int, b int) int { // প্যাকেজ লেভেলে ডিক্লেয়ারেশন
    return a + b
}

```

## ২. পুরো প্যাকেজ থেকে অ্যাক্সেসযোগ্য

প্যাকেজ লেভেলে ডিক্লেয়ার করা ফাংশন ওই প্যাকেজের যেকোনো ফাইল থেকে কল করা যায়। কিন্তু `main()` এর ভেতরের ফাংশন শুধুমাত্র ওই `main()` এর ভেতরেই সীমাবদ্ধ থাকে।

## ৩. ক্লোজার (Closure) সুবিধা থাকে না

প্যাকেজ লেভেলের ফাংশন অন্য কোনো ফাংশনের লোকাল ভেরিয়েবল সরাসরি অ্যাক্সেস করতে পারে না। একে সব ডেটা **Arguments** বা **Parameters** হিসেবে পাঠাতে হয়। অন্যদিকে, `main()` এর ভেতরের ফাংশন `main()` এর সব ভেরিয়েবল সরাসরি ব্যবহার করতে পারে।

### প্যাকেজ লেভেল বনাম ফাংশন লেভেলের তুলনা

| বৈশিষ্ট্য          | প্যাকেজ লেভেল (`func mySum()`)   | ফাংশন লেভেল (`mySum := func()`)     |
| ------------------ | -------------------------------- | ----------------------------------- |
| **কল করার নিয়ম**   | যেকোনো জায়গা থেকে (উপরে বা নিচে) | শুধুমাত্র ডিক্লেয়ার করার পর         |
| **স্কোপ (Scope)**  | পুরো প্যাকেজ জুড়ে দৃশ্যমান       | শুধুমাত্র ওই ফাংশনের ভেতরে দৃশ্যমান |
| **ভেরিয়েবল টাইপ**  | এটি একটি Identifier/Function     | এটি একটি Variable                   |
| **ক্লোজার সুবিধা** | নেই (প্যারামিটার লাগে)           | আছে (বাইরের ভেরিয়েবল পড়তে পারে)     |

### গুরুত্বপূর্ণ নোট:

আপনি যদি প্যাকেজ লেভেলে কোনো ফাংশন ভেরিয়েবল হিসেবে ডিক্লেয়ার করেন, তবে সেটি আবার `main()` এর মতোই আচরণ করবে। যেমন:

```go
var mySum = func(a, b int) int { return a + b } // প্যাকেজ লেভেলে ভেরিয়েবল

```

এক্ষেত্রেও আপনি এটি ডিক্লেয়ার করার আগে ব্যবহার করতে পারবেন না, কারণ এটি এখন একটি **Variable** হিসেবে কাজ করছে।
